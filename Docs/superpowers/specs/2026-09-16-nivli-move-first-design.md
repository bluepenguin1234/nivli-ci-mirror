# Nivli 3.0 "Move first" — design spec

Date: 2026-09-16. Author: the build team (Fable reviewing, Opus building). The owner was
not available during design, so every open question was answered here and recorded under
*Assumptions*. Anything the owner wants changed is a normal follow-up.

## 1. What it is

Nivli locks the social apps you choose until you have worked out today. Log a workout by
hand, or let Apple Health prove it (an Apple Watch run, a gym session in any app that writes
to Health), and the apps unlock until midnight. Every day you move, the streak grows.

One subscription: **$2.99 / month**. No free tier. No account, no server, no analytics.

Positioning line: **Move first. Then scroll.**

## 2. Product rules (the contract every screen and extension obeys)

| Rule | Decision |
|---|---|
| Day boundary | The device's local calendar day (midnight to midnight). |
| What unlocks | A *qualifying* workout: any workout, manual or from Apple Health, whose duration ≥ the user's **minimum** (default 20 min; choices 10, 15, 20, 30, 45, 60). |
| Manual log | Honor system. Type + duration. A log under the minimum is kept in history but does not unlock; the sheet says so before saving. |
| Apple Health | Optional. Read-only access to workouts. Background delivery so a Watch workout unlocks the apps without opening Nivli. A Health workout is deduplicated by its `UUID`. |
| Rest days | Weekly rest days (a set of weekdays, default none) and one-off "take today off" days. On a rest day nothing is locked and the streak is neither broken nor grown. |
| Streak | Consecutive days ending today (or yesterday, if today is not done yet) in which every day is a workout day or a rest day; only workout days are counted. Longest streak is kept. |
| Locking | Uses the Screen Time API (FamilyControls + ManagedSettings). Shields the user's `FamilyActivitySelection` (apps, categories, web domains). Nivli never sees app names; the system renders them. |
| Re-lock at midnight | A DeviceActivityMonitor extension with a daily schedule (00:00 → 23:59, repeating) re-applies shields at the start of every day. |
| Fail open | If the subscription is not valid (`entitlementValidUntil < now`), onboarding is incomplete, or the selection is empty: **no shields, ever**. Deleting the app removes shields (system behaviour). |
| Paywall | Hard paywall at the end of onboarding. Restore Purchases, price from StoreKit, Apple's standard EULA link, privacy policy link, renewal terms text. |
| Notifications | Optional. (a) "Apps unlocked" when a Health workout is detected in the background; (b) an evening nudge at a chosen time if today is not done. Asked once, in onboarding; declining changes nothing else. |
| Simulator / no Screen Time | Authorization failures are handled: the user can continue, the app says Screen Time is unavailable, nothing crashes. |

## 3. Assumptions (answered on the owner's behalf)

1. **Bundle ID stays `com.bluepenguin.nivli`** so the new code replaces the existing App
   Store app "Nivli" as version **3.0.0**. Extensions: `com.bluepenguin.nivli.monitor`,
   `com.bluepenguin.nivli.shield`. App Group `group.com.bluepenguin.nivli` (already exists).
2. **Subscription reuses the existing product** `com.bluepenguin.nivli.plus.monthly`
   (already created in App Store Connect at $2.99/month in group "Nivli+"). The owner
   renames its display name/description in App Store Connect; the app never shows the
   product's ASC description, only its price. The old yearly and lifetime products are
   honoured as valid entitlements (anyone who bought them keeps access) but are not sold.
3. **iOS 18.0 minimum**, iPhone only, portrait only, Swift 5 language mode, Xcode 26 on
   Codemagic — the same toolchain settings as the previous Nivli build.
4. **Design tokens and logo come from the previous Nivli** (`Brand/`, the "Ni" mark, ink
   `#142B39`, mint `#5EDCC0`, teal `#11665D` light accent, night canvas gradient). Dark is
   the default appearance; light is supported.
5. **No widgets, no Siri, no Watch app, no sharing** in 3.0. YAGNI.
6. Support and privacy pages stay at `https://bluepenguin1234.github.io/{support,privacy}.html`
   (replaced with the new pages in `Web/` when the build is submitted).
7. Build number on Codemagic = `100 + BUILD_NUMBER` so it can never collide with the old
   app's builds (the last was 14).

### 4.1 Shared state (App Group `UserDefaults`, JSON-encoded)

`NivliState` (Codable, value type, immutable updates via `with`-style helpers):

```swift
struct NivliState: Codable, Equatable {
    var onboardingComplete: Bool = false
    var selection: FamilyActivitySelection = .init()   // Codable; empty when nothing chosen
    var minimumMinutes: Int = 20
    var weeklyRestDays: Set<Int> = []                    // Calendar weekday numbers, 1 = Sunday
    var oneOffRestDays: Set<DayKey> = []
    var workouts: [WorkoutEntry] = []                    // newest last; both sources
    var entitlementValidUntil: Date? = nil               // nil = never subscribed
    var healthEnabled: Bool = false
    var reminderEnabled: Bool = false
    var reminderMinutesFromMidnight: Int = 18 * 60       // 6:00 pm
    var goals: [Goal] = []                               // onboarding answers, for copy only
    var currentFrequency: Frequency? = nil
    var dailyPhoneHours: PhoneHours? = nil
}

struct WorkoutEntry: Codable, Equatable, Identifiable {
    enum Source: String, Codable { case manual, health }
    var id: UUID                      // for .health this is the HKWorkout UUID (dedupe)
    var day: DayKey
    var start: Date
    var minutes: Int
    var kind: WorkoutKind             // run, walk, strength, cycle, swim, yoga, hiit, sport, other
    var source: Source
}

struct DayKey: Codable, Hashable, Comparable { let year: Int; let month: Int; let day: Int }
// DayKey(date:calendar:), .date(in:), .previous(in:), .weekday(in:), description "2026-09-16"
```

`SharedStore` — the only reader/writer of the App Group defaults. `load() -> NivliState`,
`save(_:)`, `update((inout NivliState) -> Void)`. Key: `nivli.state.v1`. Thread-safe enough
(UserDefaults is), no caching, no observers. A `SharedStore(suiteName:)` initialiser so tests
use a throw-away suite.

### 4.2 Pure logic (unit-tested, no Apple frameworks beyond Foundation)

- `StreakEngine.streak(state, today: DayKey, calendar) -> Int`
- `StreakEngine.longestStreak(state, calendar) -> Int`
- `StreakEngine.isRestDay(state, day, calendar) -> Bool`
- `StreakEngine.qualifyingWorkout(state, day) -> WorkoutEntry?` (first entry that day with
  `minutes >= state.minimumMinutes`)
- `StreakEngine.weekStrip(state, today, calendar) -> [DayStatus]` for the 7 dots on Home
  (`.done`, `.rest`, `.missed`, `.today`, `.future`)
- `ShieldPolicy.decision(state, now: Date, calendar) -> ShieldDecision` where
  `ShieldDecision = .open(reason: OpenReason) | .locked` and
  `OpenReason = .notSubscribed | .notOnboarded | .nothingSelected | .restDay | .workedOut(WorkoutEntry)`.
  Order of checks exactly: subscription → onboarding → selection → rest day → workout.

### 4.3 Screen Time glue (Shared, used by app + monitor)

- `ShieldController` wraps one `ManagedSettingsStore(named: .init("nivli.daily"))`.
  `apply(selection)` sets `shield.applications`, `shield.applicationCategories = .specific(...)`,
  `shield.webDomains`; `clear()` calls `clearAllSettings()`.
  `refresh(store:now:)` = load state → `ShieldPolicy.decision` → apply or clear, returns
  the decision. Used by the app on every foreground and by the monitor at interval start.
- `ActivitySchedule.startDailyMonitoring()` — `DeviceActivityCenter` with name `"nivli.daily"`,
  schedule 00:00–23:59 repeating; stops the existing one first; throws are caught and
  reported by the caller. Never called in the simulator path if authorization failed.

### 4.4 App services

- `ScreenTimeAuthorization` (@Observable): `status` (.notDetermined/.approved/.denied/.unavailable),
  `request()` async → `AuthorizationCenter.shared.requestAuthorization(for: .individual)`;
  failure → `.unavailable` with a human message.
- `HealthKitService`: `isAvailable`, `requestAccess()`, `workoutsToday(minimumMinutes:)`,
  `startObserving(onChange:)` (HKObserverQuery + `enableBackgroundDelivery(.immediate)`),
  `importToday(into store:)` — merges Health workouts into `state.workouts` deduped by UUID and
  returns whether something new qualified.
- `SubscriptionStore` (@Observable, StoreKit 2): `products`, `isSubscribed`, `validUntil`,
  `purchase(product)`, `restore()`, `listenForTransactions()`; after every change writes
  `entitlementValidUntil` into `SharedStore` (lifetime → `.distantFuture`). Product IDs from
  `AppConfig`.
- `NotificationService`: `requestPermission()`, `scheduleEveningNudge(at:)`,
  `cancelEveningNudge()`, `postUnlocked(streak:)`.
- `DayRefresher` (`@MainActor`): the single "something changed, recompute" entry point:
  import Health → shield refresh → reschedule nudge → publish `HomeSnapshot` for the UI.

### 4.5 Extensions

- **NivliMonitor** `DeviceActivityMonitorExtension: DeviceActivityMonitor` —
  `intervalDidStart` and `intervalDidEnd` both call `ShieldController.refresh`.
- **NivliShield** `ShieldConfigurationExtension: ShieldConfigurationDataSource` — returns the
  branded configuration for app / category / web domain: dark ink background, the Nivli mark
  (a PNG asset inside the extension), title "Move first.", subtitle "Log a workout in Nivli
  to unlock {app} today." plus the streak line when > 0, primary button "OK" in mint.
  Reads only `SharedStore` (streak), never StoreKit or HealthKit.

## 5. Screens

### Onboarding (8 pages, swipe disabled, progress bar on top, one primary button per page)

1. **Welcome** — breathing "Ni" mark on the night canvas, "Move first. Then scroll.",
   two lines of what Nivli does, *Get started*.
2. **What are you here for?** — multi-select chips: Build a workout habit · Cut my screen
   time · Get stronger · Feel better day to day · Sleep better. *Continue* (≥1 selected).
3. **How often do you move now?** — single: Rarely · 1–2 days a week · 3–4 days · Almost
   every day. *Continue*.
4. **How much of your day goes to your phone?** — single: About an hour · 2 hours ·
   3 hours or more · I'd rather not know. After choosing, the page reveals "That's about N
   days a year." (1h→15, 2h→30, 3h+→46, unknown→shows nothing). *Continue*.
5. **Choose the apps that wait** — explains the Screen Time permission, *Allow Screen Time*
   → system prompt → then *Choose apps* opens `FamilyActivityPicker`. Shows "N apps · M
   categories · W sites" once chosen. If unavailable (simulator, denied): explains and lets
   the user continue; Settings can retry. *Continue* enabled when something is selected or
   Screen Time is unavailable.
6. **How will Nivli know you moved?** — Apple Health card (*Connect Apple Health*, optional)
   and "Or log it yourself in two taps". Minimum picker (segmented 10/15/20/30/45/60, default
   20). *Continue*.
7. **Stay on track** — evening nudge time (default 6:00 pm) and *Turn on reminders* /
   *Not now*. Requests notification permission if turned on.
8. **Your first streak starts tomorrow morning** — summary card (apps waiting, minimum,
   Health on/off), a 7-dot preview with today highlighted, then *Continue* → Paywall.

### Paywall (full screen, cannot be dismissed until subscribed or restored)

Mark, "Unlock your apps by moving first", three benefit rows (Locks the apps you chose until
you've moved · Apple Health unlocks automatically · Streaks that make it stick), the single
plan card "Nivli · $2.99 / month" (price from StoreKit; shows an introductory offer if App
Store Connect has one), *Start for $2.99/month*, *Restore Purchases*, renewal terms
paragraph, Terms of Use (EULA) · Privacy Policy links. Loading and error states.
On success: writes entitlement, marks onboarding complete, applies shields, starts
monitoring, goes Home.

### Home

- **Status hero**: a ring. Locked → ring in ink with a lock, "Locked until you move",
  "N apps are waiting". Unlocked → ring fills mint with a check, "Unlocked for today",
  "42 min run · Apple Health" or "30 min strength · logged by you". Rest day → "Rest day".
  Not subscribed → a card that reopens the paywall.
- **Streak**: big rounded number with a flame, "day streak", longest below, 7-dot week strip.
- **Primary button**: *Log a workout* (opens LogWorkoutSheet). Hidden once unlocked; replaced
  by a quiet *Add another*.
- **Blocked apps card**: `Label(token)` rows for up to 6 apps, "+N more", *Edit*.
- **Toolbar**: Settings gear.
- Milestone celebration (3, 7, 14, 30, 50, 100, 365) — confetti + haptic, once per milestone.

### Log a workout (sheet)

Kind grid (9 kinds with SF Symbols), duration presets (10/15/20/30/45/60/90) + stepper,
"Counts toward today" / "Under your 20-minute minimum" line, *Log it*. On save: haptic,
`CelebrationView` ("Unlocked. 5-day streak."), sheet closes, Home updates.

### Settings

Apps that wait (picker) · Apple Health (connect / connected / open Health settings) ·
Minimum workout · Rest days (7 toggles) · Take today off (confirm) · Reminders (toggle, time) ·
Appearance (Dark/Light/Match iPhone) · Subscription (status, Manage, Restore) ·
Support · Privacy Policy · Terms of Use · Version. Footer: "Nivli keeps everything on this
iPhone."

## 6. Error handling

Every Apple call that can throw is wrapped; failures become a `UserFacingError`
(title, message) shown inline on the page that triggered them, never a crash. Screen Time
unavailable → explained; StoreKit unavailable → paywall shows retry; Health denied → manual
logging still works; monitoring throws → shields are still applied by the app on every
foreground (degraded but functional), and the error is logged with `os.Logger`.

## 7. Testing

- Unit: `DayKey`, `StreakEngine` (rest days, gaps, today-not-done, longest), `ShieldPolicy`
  (each open reason and the order), `SharedStore` round-trip, `WorkoutEntry` dedupe/import
  logic, `SubscriptionStore.validUntil` mapping (pure helper), `OnboardingModel` gating
  (which pages can continue), `PhoneHours.daysPerYear`.
- UI: launch + first onboarding page visible.
- Static: `Scripts/preflight.py` (plists, assets, privacy manifests, imports, secrets, product
  IDs vs StoreKit file, entitlements vs Codemagic list).
- Compile/test on Apple hardware: Codemagic `ios-compile` / `ios-unit` (owner starts).

## 8. Compliance notes baked in

- 3.1.2 subscriptions: price, period, EULA + privacy links, restore, renewal text.
- 5.1.1 / HealthKit: usage string explains reading workouts; privacy policy names Health.

- Privacy manifests in all three bundles; "Data Not Collected".
- `ITSAppUsesNonExemptEncryption = false`.
